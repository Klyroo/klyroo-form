# Changelog

All notable changes to this project are documented in this file. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `Klyroo.Form.Maui`, native .NET MAUI views with no WebView for the controllers of `Klyroo.Form.Core`, drawn with the inputs of `Klyroo.UI.Maui`: `KlyFormEngine<TModel>`, `KlyFormPage<TModel>`, `KlyFormFieldView<TModel>`, `KlyFieldTemplate<TModel, TValue>`, `KlyFormProvider` (with a `FormService` for typed overlays), `KlyFormErrorSummary`, `KlyFormNavigationGuard` (through `Shell.Navigating`), and `KlyDynamicFormEngine`, `KlyDynamicFormPage` and `KlyDynamicFieldView` for runtime schemas. It is not in `Klyroo.Form.slnx` (it needs the MAUI workload). `Klyroo.Form.Core` shows its internals to it and to its tests, as it does to `Klyroo.Form`.

### Changed

- The ecosystem table of the README describes Klyroo.Display by what it keeps (code highlighting, secret and file list components, media player controls and file preview), since its read-only display blocks are typed components of Klyroo.UI.
- `Klyroo.Form.Core` is about 4 KB smaller: the four internal helper types that were records (`ValidatorRule`, `AsyncValidatorRule`, `RawNumber` and the write plan step) are plain classes, because nothing compared, printed or copied them and each record added ten members to the assembly. No public API changes.

- **Breaking:** the tone and the kind of an info block are enums. `FormSchemaBuilder<TModel>.Info(..., tone:)` takes a `FormInfoTone?` (`Neutral`, `Info`, `Success`, `Warning`, `Error`), and `DynamicFieldSchema.DisplayTone` and `DisplayKind` are a `FormInfoTone?` and a `FormInfoKind?` (`Callout`, `Text`). The markup is the same; the case-insensitive text and the fallback to the default for an unknown value are gone with the text.
- BREAKING (markup): the element ids of a form carry a number that is unique per form instance, so two forms with the same field keys on one page (an inline form and an overlay of the same schema) no longer share ids: `kly-ff-email` is now `kly-ff-3-email`, and the same goes for the ids of the label, description, help, error, tab, list cell and error summary elements. `for`, `aria-describedby`, `aria-labelledby`, the error summary links and the focus after a failed submit use them. A CSS or test selector on `#kly-ff-...` should select on `[data-form-field=...]` (or on the suffix of the id) instead.

### Documentation

- The documentation teaches the typed API first. `README.md`, Getting started, the guides, Concepts, the FAQ and Platforms use `FormSchema.For<TModel>`, `FormController<TModel>`, `KlyFormEngine<TModel>`, `FormService.CreateFormAsync<TModel>`, `KlyFieldTemplate` and the typed rules and hooks in every recipe (validation, server errors, async checks, busy save, conditional fields, wizard, sections, dialog, repeatable rows, prefill and reset, custom control, uploads, tests). The runtime mode has its own page, [Forms defined at runtime](docs/runtime-forms.md): when to use it, how to build a schema from stored data, and the same recipes on dictionaries. The code samples are compiled and run.
- The guides now say that a method group or a lambda given to `OnSubmit` of `KlyFormEngine<TModel>` stops Razor from inferring `TModel` (write `TModel="Order"`), that `Reset()` of a typed controller returns to the baseline while the dynamic one returns to the defaults, and the star picker sample writes `aria-pressed` as `"true"` or `"false"` (a Blazor `bool` attribute rendered no value).
- `docs/internal-contract.md` is titled as an internal note for contributors, in the page and in the navigation, and `skills/klyroo-form/SKILL.md` lists the typed API first and the runtime mode last.

### Fixed

- Text fields, selects and text areas have a 3:1 border in light and dark, checkboxes and radios have a 44 pixel row on phones, the section sidebar of a form page follows the width of the form rather than of the window, and the page title shares the baseline of its progress note.
- An enum member shown with `AsRadio()` had no options, so its radio group rendered no choice: the members of the enum are now its options for a radio group as they are for a select.
- An info block whose `DisplayTone` was cast from a number outside `FormInfoTone` rendered `data-tone="7"` and the muted text of a tone with no color. It now renders as neutral, in the classes and in the attribute.
- The `Min` and `Max` of a number field are checked on the exact number, not on its `double` approximation. `FormJsonCoercion` (the check behind `IFormFieldAccess.TrySet`, so an agent) checked the double, and then the codec swapped in the exact decimal without checking again, so a `decimal` field with `Range(0m, 100m)` accepted `100.0000000000000001` and a `long` field accepted `9007199254740993` over a maximum of `2^53`. The validation of typed and dynamic number fields (`Validate`, `SubmitAsync`) had the same flaw for a decimal or a long control value. Both compare the value with the number its bound reads as (the whole number a whole double holds, else the shortest text of the double), so a bound of `0.1m` still accepts `0.1m`. A value written outside the bounds is now refused with the "must be at least/at most" reason.
- `KlyrooFormOptions.CustomField` (dynamic) and `CustomField<TValue>` (typed) no longer overwrite each other when they use the same key: renderers are kept by key and value type, so a dynamic renderer, and typed renderers of different value types, coexist under one key.
- A typed overlay opened in `Fullscreen` mode gets the same centered width wrapper as the runtime overlay.
- A `KlyFormEngine<TModel>` or `KlyFormPage<TModel>` whose `Model` goes from an instance to `null` resets the form to the state of a new model, so what the form shows is what a submit then creates.

### Added

- A documentation site at https://klyroo.github.io/klyroo-form/, built from `README.md` and `docs/` and published by `.github/workflows/docs.yml` (the build is `docs-site/` of klyroo-stack). `docs/site.yml` sets the title, tagline, install command, NuGet packages, order of the pages and accent color; the Markdown files themselves are read as they are.
- Typed components: `KlyFormEngine<TModel>` and `KlyFormPage<TModel>` render a `FormSchema<TModel>` or a `FormController<TModel>` with a `Model`, and Razor infers `TModel` from `Form`, `Schema`, `Model` or `OnSave`. `OnSave` is `Func<TModel, CancellationToken, Task<bool>>`, `OnSubmit` is `EventCallback<TModel>` and `OnCancel` an `EventCallback`. A submit writes the values into the `Model` (all or nothing, put back when a step fails) or creates a new model when there is none. They have the shell, labels, reset, error summary and focus handling of the dynamic components.
- `KlyFormFieldView<TModel>` draws one field of a typed controller (from the enclosing form component, a `CascadingValue` or its `Form` parameter) for a layout of your own.
- `KlyFieldTemplate` draws the control of one typed field with a `FormControlContext<TValue>` (`Value`, `Current()`, `Set`, `Commit`), over a non-generic `FormControlContext` (`Id`, `Error`, `Disabled`, `Required`, `Validating`, `LabelledBy`, `DescribedBy`, `ErrorId`, `Blur()`, and `Text` and `SetText(string?)` for raw inputs). `FormFieldBuilder.AsCustom(key)` declares a field whose control you provide, and `KlyrooFormOptions.CustomField<TValue>(key, renderer)` registers a renderer for the whole app; a field of another value type shows the "no renderer" notice.

- `KlyFormErrorSummary` and `KlyFormNavigationGuard` take an `IFormRuntime`, so they serve a `FormController<TModel>` as well as a `DynamicFormController`.
- New package `Klyroo.Form.DataAnnotations`: `UseDataAnnotations()` and `FromDataAnnotations()` read the attributes of a typed schema: `[Required]`, `[StringLength]`, `[MaxLength]`, `[Range]` (mapped onto the engine's own rules and localized messages), `[MinLength]`, `[RegularExpression]`, `[EmailAddress]`, `[Phone]`, `[Url]`, `[CreditCard]`, `[Compare]` (validator rules), `[Display]` (name, description, prompt, order), `[Editable(false)]`, `[ReadOnly(true)]` and `[DataType]`, use an `ErrorMessage` the developer set, and run custom `ValidationAttribute`s, attributes on the class and `IValidatableObject` at submit, with errors mapped to field keys or the form.

- `FormFieldKind.Custom` with `DynamicFieldSchema.CustomKey`: a control you provide as a `RenderFragment<DynamicControlContext>`, registered once with `KlyrooFormOptions.CustomField` (`AddKlyrooForm(f => f.CustomField(key, renderer))`) or per component with the `FieldTemplates` parameter of `KlyDynamicFormEngine`, `KlyDynamicFormPage` and `KlyDynamicFieldView`. It is a stateful field, validated and part of the output.
- `FormFieldKind.File`, rendered with `InputFile`, with `DynamicFieldSchema.Accept` and `MaxFileSize` (and `Multiple`) checked on validation in `Klyroo.Form.Core`. The value is the UI-free `FormFileValue` (name, size, content type, `OpenReadAsync`, `FromBytes`, `Matches`, `FormatSize`), or a `List<FormFileValue>` with `Multiple`. Files are left out of drafts.
- Localization: the built-in texts of the components (`FormTexts`, one set per Klyroo.UI locale in `FormLocales`) and the built-in validation messages (`FormMessages`, in `Klyroo.Form.Core` so they work without Blazor, one set per locale in `FormMessageLocales`) follow the locale in twelve languages. English and French are reviewed, the others are drafts. `AddKlyrooForm(f => f.Texts(code, change))` changes a set, `DynamicFormSchema.Messages` and `DynamicFormController.Messages` choose the language of one form, and `FormMessageLocales.Resolve(code)` picks a set for a culture name.

They run in the background after blur and while editing, stale runs are cancelled, and `SubmitAsync`, `NextStepAsync` and the new `DynamicFormController.ValidateAsync` wait for them. `IsValidating(key)` and `HasPendingValidation` report a run, and the components show a pending state next to the field.
- `KlyFormNavigationGuard`, a `NavigationLock` that follows `DynamicFormController.IsDirty`: it asks the browser to confirm external navigation while the form is dirty and confirms in-app navigation with `window.confirm` or your `ConfirmLeave`.
- `DynamicFormController.ExportState()` and `RestoreDraft()` with `FormDraft` (and `ToJson` and `FromJson`, written without reflection). A restored draft keeps the original baseline, so it is still dirty; passwords and one-time codes are left out unless asked for.

It uses no reflection over the target type, so it stays AOT and trim compatible.

An error set with `SetError` on a key that matches no field is form-level, and `KlyFormErrorSummary` renders them at the top of `KlyDynamicFormEngine` and `KlyDynamicFormPage`, followed by the field errors after a failed submit or Next, each as a button that focuses the field.

- `Klyroo.Form.DataAnnotations` retargeted onto the typed schema: `UseDataAnnotations()` and `FromDataAnnotations()` keep their names and mapping, `AllMembers()` declares the remaining members, and attributes of a list item are applied to its columns.
- `FormMessages.WholeNumber`, `NumberOutOfRange` and `InvalidIdentifier`, translated in the twelve locales (English and French reviewed), are the messages a typed form adds for integers, numbers outside the type of the member and `Guid` (`InvalidValue` below covers every other type). `DynamicValidatorRule.LocalizedMessage` computes the message of a rule from the messages of the controller when it fails.

### Fixed

- `ApplyTo` and `SubmitAsync(save, target)` write the edited columns of a repeatable list into the item each row was loaded from, instead of replacing every item with a new one: members that are not columns survive, a new item is created only for an added row, removed rows are dropped, the order is kept, and a list nobody changed is not touched. The collection is changed in place when it is an `ICollection<T>` that can be (`List<T>`), and put back with the rest of the write when a step fails. After a successful save into a target the rows stand for the items the target holds, so a form that stays open keeps what the save step set on them. `CreateModel` and a write into another model create new items and never change the rows of the model the form was loaded from.

- A getter-only collection member (`public List<Line> Lines { get; } = new();`) of a `List` or a `MultiSelect` is written in place instead of being silently skipped. One whose type cannot be changed in place (an array, `IReadOnlyList<T>`, `IEnumerable<T>`) is refused when the schema is built, and one that is read-only at run time makes `ApplyTo` throw before anything is changed.
- A `List` or a `MultiSelect` reached through a chain (`s.List(m => m.Inner.Lines, ...)`) is refused when the schema is built, with a message that points to `Group(...)`. It used to build, read no rows and throw on the first write.

- `FormSchema<TModel>.MultiSelect(m => m.Roles)` gets the handle of a multiple choice from the schema, as `List` does for a list. `Field<IReadOnlyList<TElement>>(m => m.Roles)` finds it too, and `Field(m => m.Roles)` explains which method to use instead of failing with a type message. Before, no call of the schema could return the handle of a `List<T>` member declared with `MultiSelect`.

- `IFormFieldAccess.TrySet` on a typed field goes through the codec of the field (`FormCodec<TValue>.TryReadJsonControl`), so a number keeps every digit it had: `1234567890123456789.1234567890` for a `decimal`, `9007199254740993` and `long.MaxValue` for a `long`, `ulong.MaxValue` for a `ulong`. It stored a `double` before, which rounded them or refused the largest ones. The option label matching and the other coercion rules are unchanged, and a dynamic `Number` field still stores a `double`.

- `FormMessages.InvalidValue` (translated in the twelve locales) is the validation error of a typed field whose control holds something that is not a value of the member type: `abc` in a `DateOnly` or `DateTimeOffset` restored from a draft, two texts that are not dates in a `FormDateRange`, free text from a custom control. `Validate` and `SubmitAsync` report it, for a field and for a cell of a list, whatever the validation mode. The value used to pass `Validate`, and the submit then threw an `InvalidOperationException` from the write.

### Changed

- BREAKING: the runtime (dictionary) mode moved to the `Klyroo.Form.Dynamic` namespace with a `Dynamic` prefix: `DynamicFormSchema`, `DynamicFieldSchema`, `DynamicStepSchema`, `DynamicSectionSchema`, `DynamicTabSchema`, `DynamicFormController`, `DynamicValidatorRule`, `DynamicAsyncValidatorRule`, `DynamicControlContext`, `DynamicFormService` (with `DynamicFormOutcome`), `KlyDynamicFormEngine`, `KlyDynamicFormPage` and `KlyDynamicFieldView` (formerly `KlySchemaField`, with a new `Key` parameter). Behavior is unchanged, and the engine tests are kept under the new names. The classes are now thin public views over an internal `FormEngine` and `FieldNode` tree that the typed mode shares.
- BREAKING: `FormDraft.Values` is internal; a draft is still created with `ExportState()` or `ExportDraft()`, and written and read with `ToJson` and `FromJson`.
- BREAKING: the typed binding layer is replaced by the typed schema above. `FormModel`, `FormModel<TModel>`, `FormModelBuilder`, `FormNestedBuilder`, `FormFieldBuilder<TValue>`, `FormFieldSettings`, `FormFieldConvention(member, settings)`, `FormModelValidator` and `FormModelErrors` are removed; `FormValueMap`, `FormWritePlan`, `FormNullability` and `FormFieldBinding` became the internal codec and write layer, and keep every behavior their tests prove.

- `DynamicFormController.IsFieldDisabled` is `true` for every field while `IsSubmitting` is `true`, and the components render the controls disabled during a submission.
- `DynamicFormController` implements `IDisposable` (it cancels the asynchronous validations still pending) and has `CancelPendingValidations()`. `DynamicFormService` disposes the form it closes or replaces, and `KlyDynamicFormEngine` disposes the controller it creates.
- `DynamicFieldSchema.MaxFileSize` defaults to 10 MiB (`FormFileValue.DefaultMaxSize`) instead of no limit, because a chosen file is now read into memory when it is chosen. `FormFileValue.FormatSize` takes a decimal separator and unit names, and `FormMessages.FileSize` formats a size for the language of the messages.
- `KlyDynamicFormEngine.SubmitLabel` is `string?` and defaults to the `Submit` text of the current locale instead of the literal `Submit`; `KlyFormNavigationGuard.Message` defaults the same way. `KlyDynamicFieldView` derives from `KlyComponentBase`, which gives it `Class` and unmatched attributes like the other components.
- `KlyFormProvider` hosts its overlay in `KlyModal` (`Modal`, `Fullscreen`) and `KlySlideover` (`Drawer`) of Klyroo.UI instead of a hand-made `div`: the native modal dialog traps focus, closes on Escape and on a click on the backdrop, and returns focus to the opener. It cannot be dismissed while the form saves. The `form-provider-dialog` and `form-provider-overlay` class names are gone; the overlay carries `data-slot="form-provider-overlay"`, `data-mode` and `data-open` on a wrapper and `data-form-dialog` on the dialog.
- `GetValue<T>` no longer rounds a fraction into an integer type (`GetValue<int>` on 3.5 returned 4): it returns `default`, as it does for any other value that does not fit the type.
- Per-field error messages no longer carry `role="alert"`: they stay linked to the control with `aria-describedby`, and the live region and the error summary announce errors once for the whole form.
- `NextStepAsync` and `PreviousStepAsync` refuse a call while another step change is running, and `SubmitAsync` refuses one during a step change.
- `AutoComplete` is a text input with `datalist` suggestions instead of a select list. It stores the value of the option whose label matches the text (ignoring case) or whose value equals it, or the text itself.
- `Watch` now also runs after `ResetField` changes a value, after a row of a repeatable list is added or removed, and, for a child of a list, after its cell changes. `Reset` still does not call it.
- `Validate` removes the validation errors of fields that are no longer in effect, and `HasBlockingErrors` ignores them.
- A `Number` control stores a `decimal` instead of a `double` when the digits typed (or loaded from a model or a draft) do not fit a double, and shows every digit of a `decimal`, `long`, `ulong` or `float` (`0.1f` shows `0.1`). Up to 15 digits it still stores a `double`. In the typed binding, `long.MaxValue`, `ulong.MaxValue` and a `decimal` with 28 digits round-trip exactly, and a value that does not fit the type of the member (`9223372036854775808` for a `long`, `1e39` for a `float`) is a validation error with a localized message instead of becoming `0`.
- The typed `Write`, `Create` and `OnSave` refuse a value that is there but is not a value of the member type (text for a number, a number that does not fit) with an `InvalidOperationException` instead of writing `default`, and an enum member written from a number accepts one that no member has when it fits the underlying type.
- The text a `DateTime` or `TimeOnly` gets in a control keeps the milliseconds (`yyyy-MM-ddTHH:mm:ss.fff`).

### Removed

- `DynamicStepSchema.Root`, which was reserved and never read.

### Fixed

- Typed model binding, `Write`: an enum value that has no name (`(Status)42`), and the ticks and the `Kind` of a `DateTime` (and the ticks of a `DateTimeOffset` or a `TimeOnly`), are kept when the user did not change the field, instead of becoming `0` or `null`, truncated to the second and `Unspecified`. A typed date and time takes the `Kind` of the value it replaces (`Unspecified` for a default one).
- Typed model binding: `FormModel.For` refuses a struct model with an `ArgumentException`, because `Write` set the members of a copy and returned the original.
- Typed model binding: `Write` is all or nothing. Every value is converted and every object on the way is checked before the first member is set, a setter that throws puts back the members already set, and a save step (`SubmitAsync`, `OnSave`, `OnSaveOutput`) that returns `false` or throws leaves the target as it was. A form with model checks (`Validate`, `UseDataAnnotations`) and a model that cannot be created fails in `FormModel.For` instead of at every submit.
- Typed model binding: the nullable annotation of a string member is read defensively. When the metadata is not available (a trimmed app with `System.Reflection.NullabilityInfoContext.IsSupported` off) an empty input gives an empty string, never a `null` the member may not hold, unless `NullWhenEmpty` says otherwise.
- `Klyroo.Form.DataAnnotations`: the messages of the rules the attributes become (`[MinLength]`, `[RegularExpression]`, `[EmailAddress]`, `[Compare]`, `[StringLength]` with a minimum, `[Range]` with decimal, text or exclusive bounds, and the others) and their `[Display]` name are worked out when the rule fails, so a form shared by several cultures shows the message of the culture of the validation. The label, description, placeholder and `[Required]` message are still fixed when the form is built, and the documentation now says exactly which attribute becomes an engine rule and which a validator rule.
- Editing a field while the form was submitting changed values that were being validated or saved.
- An exception thrown by `OnSave`, an asynchronous rule, a hook or `OnSubmit` ended the Blazor Server circuit. `KlyDynamicFormEngine` and `KlyDynamicFormPage` now log it and show a localized form-level notice (`FormTexts.SomethingWentWrong`), and `IsSubmitting` resets.
- An edit that replaced a running asynchronous rule could surface as an `OperationCanceledException` from `SubmitAsync` or `ValidateAsync`, and could let a submit succeed with a value whose rule had not answered. `ValidateAsync` now runs the rules again for missing or stale results, reports failure if they keep going stale, and makes no second call for a value a background run is already checking.
- After a save, the baseline was the state at the end of the handler instead of the values the handler received, so an edit made meanwhile was marked clean.
- `ExportState` put password and one-time code columns of repeatable lists, and file columns, in the draft, and `RestoreDraft` filled `File` and `Custom` fields from stored text. They are now left out and skipped.
- A chosen file kept a live stream on the `InputFile` element, so a step change, a hidden field or removing another file left the value unreadable. Files are read into memory at selection time, bounded by `MaxFileSize`.
- The live region of the error summary announced again on every edit after a failed submit. It now speaks once per failed attempt, when a form-level error appears, and when the last error is gone.
- `GetValue<TEnum>` accepted a comma combination for an enum without `[Flags]`, and `GetValue<bool>` rejected a boxed `1` or `0`.
- Validation messages showed numbers and file sizes with the invariant format in every language (`3.5`, `1.5 MB` in French). They follow the separator and units of the language (`3,5`, `1,5 Mo`).
- The sections guide put `NavigationLock ConfirmExternalNavigation="@_form.IsDirty"` on a page that never re-renders when the user types, so the browser prompt never turned on. `KlyFormNavigationGuard` re-renders itself when `IsDirty` changes.
- The overlay of `KlyFormProvider` was a `div` with `role="dialog"`: focus was not trapped, Escape did nothing and focus was lost on close.
- `GetValue<T>` returned `default` for `Nullable<T>`, `DateOnly`, `TimeOnly`, `DateTime`, `Guid` and enum targets, which `Convert.ChangeType` cannot produce from the strings the controls store.
- A cross-field error stayed on screen after the other field was fixed (a confirm password that now matched, a `RequiredWhen` whose condition no longer held), and `HasBlockingErrors` stayed `true`. After a value changes, the controller now validates again the touched fields that show an error.
- `Validate` ignored a blocking error set with `SetError` on a key that matches no field, so a form-level failure did not stop `SubmitAsync`. It now fails on any blocking error that is form-level or on a validated field.
- Two quick clicks on Next ran `OnBeforeNext` twice and skipped a step.
- `OnSubmit` of the components ran after the submission was over (`IsSubmitting` already reset, snapshot already retaken), so an API failure there could not keep the form dirty. Use the new `OnSave`.
- Hidden and omitted columns of a repeatable list are left out of the rows of `BuildOutput`, like hidden and omitted fields.
- `KlyDynamicFormPage` rendered only the top-level fields of a section, each as an unlabelled text input: the children of containers and tabs never showed although they were validated, and repeatable lists were text inputs. It now renders fields like `KlyDynamicFormEngine`, and it is a `form` element, so Enter submits it.
- The children of a hidden `Group`, `Card` or `Object`, the fields of a hidden tab or section, and the fields of a step skipped by `SkipWhen` were still validated and output. They are now left out of validation and `BuildOutput`, and keep their values in the state.
- A `Tabs` field without tabs, or a container without `Fields`, became a stateful field rendered as a text input. Containers are now layout only and render nothing when empty.
- A stepped form whose first step is skipped started on it, and `Reset` returned to it. Both now go to the first step that is not skipped, and `IsFirstStep` and `IsLastStep` look past skipped steps, so Back is hidden and Submit shows on the last reachable step.
- Editing a field with `Trigger = Submit` left its last validation error on screen; the error is now cleared on change, without validating.
- `DynamicFormService.CreateFormAsync` called while another form was open left the replaced form's task pending forever. It now completes with `IsCompleted = false`.
- Repeatable lists in `KlyDynamicFormEngine` did not show the list's own error, required marker, description, hint or help, ignored `Disabled` and `DisabledWhen`, and had no `DirtyCheck` reset.
- A `Switch` showed its label twice, and the `Hint` and `DirtyCheck` reset of checkboxes and label-less fields were not rendered.
- The label of a radio group pointed to an id that no element had. The group now has an id and `aria-labelledby`.
- `MaxLength` was not rendered as `maxlength` on `Textarea` and `Password` inputs.
- Pressing Enter in a field of a wizard before its last step submitted the whole form; it now moves to the next step.
- A `Slider` without a value showed the browser's midpoint. It now shows `Min` (or 0) and keeps `null` in the state until the user moves it.

- A form opened with `DynamicFormService` ran validation, `OnBeforeSubmit` and `OnSubmit` twice when submitted from its button.
- `Required` on a `Checkbox` or `Switch` field now requires it to be checked; an unchecked box no longer passes. A switch where off is a valid answer must not be `Required`.
- `DynamicFieldSchema.MaxLength` is now validated by the controller, not only rendered as the `maxlength` attribute.

## [0.1.0-preview.1] - 2026-11-24

### Added

- `Klyroo.Form.Core`: a headless `FormController` driven by a declarative `FormSchema`, with 31 `FormFieldKind` values, no UI dependency and NativeAOT compatibility.
- Validation with required and required-when checks, number bounds, password requirements, custom validator rules, four validation modes and three triggers, plus `SetError` for server-side errors.
- Conditional fields (`Condition`, `RequiredWhen`, `DisabledWhen`) and value transforms (`TransformInput`, `TransformOutput`), with hidden fields left out of validation and output.
- Dirty tracking against an initial snapshot, with per-field and per-section reset and a new snapshot after a successful submit.
- Multi-step forms with skippable steps and async `OnBeforeNext` and `OnBeforePrevious` hooks, and sectioned page forms with a completion status per section.
- Repeatable rows (`ArrayList` and `ArrayTable`) and tabbed, grouped and card containers.
- `FormService` and `KlyFormProvider` to open a form as an overlay and await its `FormSubmitOutcome`.
- `Klyroo.Form`: the `KlyFormEngine`, `KlyFormPage` and `KlyFormProvider` Blazor components and `AddKlyrooForm()`, building on Klyroo.UI.
