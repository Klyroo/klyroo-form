# Klyroo.Form Skill

Declare every form with the typed API. Use the runtime mode (last section) only when the fields are not known at compile time, for example a form stored as JSON or in a database.

## Typed forms

- Declare a form from a C# model with `FormSchema.For<TModel>(s => { ... })` in `Klyroo.Form.Core`. The builder returns a handle per field (`var company = s.Field(m => m.IsCompany)`), so a later condition points at it: `s.Field(m => m.CompanyName, f => f.Required(c => c.Get(company)).VisibleWhen(c => c.Get(company)))`. Keys follow the members and nested members give dotted keys. Keep the schema in a static member or a field: a new instance makes a component start a new controller.
- Settings are methods on the field builder: `Required`, `Label`, `Rule(value => ..., message)`, `RuleAsync(...)`, `DependsOn(handles)`, `Default`, `OnChange`, `VisibleWhen`, `DisabledWhen`, `Trigger`. Kind-specific ones exist only for the types they fit: `AsTextarea`, `AsPassword`, `MaxLength` (string), `Range`, `AsSlider`, `AsRating` (numbers), `AsSwitch` (bool), `Options`, `AsRadio` (any), `Accept`, `MaxFileSize` (files). Structure: `Group`, `List` (repeatable rows: a row is written back into the item it was loaded from, so members that are not columns survive; a list is a direct member, inside `Group` for a nested one), `MultiSelect` (get its handle again with `schema.MultiSelect(m => m.Roles)`), `Step` (with `skipWhen`), `Section`, `Card`, `Tabs`, model checks with `Validate`, and `Field<TValue>("key")` on the builder for a field that is not in the model (keep the handle it returns).
- Run it with `new FormController<TModel>(schema, model)`: `Get(field)`, `TryGet`, `Set(field, value, markTouched)`, `GetError(field)`, `SetError(field, message, blocking)`, `CreateModel()`, `ApplyTo(target)`, `Rows(list)`, `AddRow`, `RemoveRow`, `ExportDraft()`, `Reset()` (back to the baseline) and `Reset(model)` (load and re-baseline), and `SubmitAsync(save, target)`, which writes the target, runs the checks and hooks, saves, and puts back the members it wrote when anything fails (what the hooks and the save step did is not undone). `Get` gives the default of the type, or an empty list for a list or a multiple choice, while a field is empty or holds text that is not a value; `TryGet` says which. Text that is not a value (a draft with `abc` in a date) is a field error in `Validate` and `SubmitAsync`, never an exception. Dispose a controller you create.
- Hooks live on the builder: `s.OnBeforeSubmit(async (model, form) => ...)` (return `false` to cancel, after `form.SetError(handle, message)`), `s.OnSubmit`, `s.OnBeforeNext((form, stepIndex) => ...)`. A check against a service while the user types is `f.RuleAsync(async (value, form, ct) => message-or-null, debounce)`.
- Add the `Klyroo.Form.DataAnnotations` package and `s.FromDataAnnotations()` (or `UseDataAnnotations()`) to read `[Required]`, `[Range]`, `[Display]` and the other attributes and to run `IValidatableObject` at submit.
- Render a typed form with `<KlyFormEngine Schema="schema" Model="model" OnSave="SaveAsync" />` (or `KlyFormPage` for sections; `TModel` is inferred from `Schema`, `Model`, `Form` or `OnSave`, keep the model non-null). A method group or lambda given to `OnSubmit` stops the inference: write `TModel="Order"`. `OnSave` gets the model and returns `Task<bool>`, `OnSubmit` is `EventCallback<TModel>` raised after a successful save, a submit writes into `Model` all or nothing. Pass `Form="controller"` plus `Model` when the page needs the controller (to call `SetFormError`, `Reset(model)` or to give it to `KlyFormNavigationGuard`).
- Draw one field in your own layout with `<KlyFormFieldView Field="@handle" />` inside the form component or a `CascadingValue` of the controller. Draw a control with `<KlyFieldTemplate Field="@handle" Context="c">` (a `FormControlContext<TValue>`: `Value`, `Set`, `Commit`, `Blur`, `Id`, `Error`, `Text`, `SetText`), or declare `f.AsCustom("key")` and register `AddKlyrooForm(o => o.CustomField<TValue>("key", renderer))`. On a custom control write `aria-pressed="true"` or `"false"` as text: a Blazor `bool` attribute renders without a value.
- Register with `AddKlyrooForm()` and mount `KlyFormProvider` for overlays: `FormService.CreateFormAsync(schema, model, mode)` returns `FormSubmitOutcome<TModel>` (`IsCompleted`, `Model`).
- Save with `OnSave` (or `SubmitAsync(save, target, ct)` without the component) so `IsSubmitting` stays true during the save and the form stays dirty on failure; use `SetFormError` for failures that belong to no field.
- Use `DependsOn` for cross-field rules, `RuleAsync` for per-field checks that need I/O, `KlyFormNavigationGuard` with `ExportDraft()` and `RestoreDraft(FormDraft.FromJson(json))` for unsaved changes, and `FormFileValue` members (`FormFileValue?` or `List<FormFileValue>`) for uploads.
- `FormController<TModel>` implements `IFormRuntime`: `Fields` lists `IFormFieldAccess` with `TrySet(JsonElement)`, `WriteValue(Utf8JsonWriter)`, `Clear`, `Toggle` and `Reset`, for agents.
- Texts and validation messages follow the Klyroo.UI locale: change them with `AddKlyrooForm(f => f.Texts("fr", t => t with { ... }))`, or set `Messages` on the controller without Blazor.

## Forms defined at runtime

Only for a form that is data, built at runtime with values keyed by name, such as a form stored as JSON or in a database. Namespace `Klyroo.Form.Dynamic`: `DynamicFormSchema`, `DynamicFieldSchema` (a `FormFieldKind`, `Validators`, `AsyncValidators`, `Condition`, `RequiredWhen`, `DependsOn`), `DynamicStepSchema`, `DynamicSectionSchema`, `DynamicFormController` (`SetValue`, `GetValue<T>`, `GetError`, `BuildOutput()`, `SetError`, `ExportState()`), `DynamicFormService` and the components `KlyDynamicFormEngine`, `KlyDynamicFormPage` and `KlyDynamicFieldView`. The library does not define a storage format: map your stored description to `DynamicFieldSchema`. Save with `OnSave` on the component (or `SubmitAsync(handler, ct)`). A custom control is a `FormFieldKind.Custom` field with a `DynamicControlContext` renderer, registered with `AddKlyrooForm(f => f.CustomField(key, renderer))` or the `FieldTemplates` parameter. `Reset()` of a dynamic controller returns to the defaults, unlike the typed one. See docs/runtime-forms.md.
